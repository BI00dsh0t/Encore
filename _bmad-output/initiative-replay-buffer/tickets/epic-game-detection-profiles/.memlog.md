topic: Game Detection and Game Profiles
updated: 2026-10-25T20:33
---


- (requirement) R1 (parent R23): A game is detected within 5 s if it runs fullscreen or borderless, if Windows identifies it as a game, or if it was added by hand. It stays detected until its process exits. Processes under the app's install folder are never detected. Game processes are opened only with `PROCESS_QUERY_LIMITED_INFORMATION` (architecture AD-12).
- (requirement) R2 (parent R24; architecture AD-18, AD-19): With several detected games, the one in focus for 10 consecutive seconds becomes the Target Game. A running game Recording blocks the switch, and the switch is re-evaluated as soon as that Recording stops.
- (requirement) R3 (parent R25): A Game Profile is created on first detection, with its id from the one `Canonicalize(path)`. It's named from the executable's product name read on disk, can be renamed, and inherits Global Settings. A profile marked Ignored never becomes the Target Game, and Ignored can be undone. The profile and its attributes are written through the settings op queue.
- (requirement) R4 (parent R26; architecture AD-21): The OutputPathAllocator is the only producer of output paths.
- (requirement) R5 (parent R23, R25 user-facing part): The Main App lists Game Profiles. Each one can be renamed, Ignored, and have Recordings switched on or off; games can also be added by hand (an executable path sent to the engine).

- (requirement) R2 (parent R24; architecture AD-18, AD-19): With several detected games, the one in focus for 10 consecutive seconds becomes the Target Game. A running game Recording blocks the switch, and the switch is re-evaluated as soon as that Recording stops. When the Target exits, another detected game takes over at once, and on a cold start the Target is chosen at once. Only `target.changed` drives capture: GameMonitor proposes, and the SessionOrchestrator commits.
- (requirement) R4 (parent R26; architecture AD-21): The OutputPathAllocator is the only producer of output paths, `<Output Folder>\<profile folder>\<Game>_<yyyy-MM-dd_HH-mm-ss>.mp4`, built from the live profile name and the QPC time of the press or start. Characters Windows doesn't allow are replaced, a path is reserved with `CREATE_NEW` (adding `_2`… on a collision), profile folder names are unique, `Monitor Recordings` is reserved, and renaming a profile affects new files only.
