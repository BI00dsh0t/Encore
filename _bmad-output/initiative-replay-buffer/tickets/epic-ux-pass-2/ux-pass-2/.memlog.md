- (event) Headless run for the coordinator (2026-11-04). Builder's words 2026-11-05: 'We need to do another pass on UX. The library is missing basic list functionality, like multi select.' and 'The track layout is convoluted and makes no sense to an end user.' Overrides epic 7's 'one item at a time, no multi-select in v1'.
- (decision) Workspace is ux-pass-2/ beside the epic file, not ux-ux-pass-2/: the epic slug already starts with ux, and the coordinator named ux-pass-2.
- (decision) The spines extend epic 9's ux-modern-ui DESIGN.md and EXPERIENCE.md; they don't restate them. This EXPERIENCE.md owns the Library list, Audio Tracks and the other gaps; DESIGN.md here is an addendum of new tokens-only components (selection, command bar, track card, source row, picker, welcome card).
- (decision) Protagonist: Sam, a gamer who isn't a developer, installs it to replace ShadowPlay. The builder stays the one real user; Sam keeps every flow honest about jargon.
- (decision) Library: the ItemsControl becomes an extended-selection list (Explorer conventions: click, Ctrl+click, Shift+click, Ctrl+A, arrows, Shift+arrows, Ctrl+arrows and Ctrl+Space, Esc clears), still virtualized and grouped.
- (decision) Library bulk actions send today's per-item commands one at a time (library.setFavourite, library.delete) and summarise failures; no new Contracts message.
- (decision) Favourites are protected from Delete, single or many: Delete skips Favourites and says so; unstar to delete. Changes 7.7's single delete of a Favourite. For the builder's review at 10.1.
- (decision) Copy puts every selected file on the clipboard as one file drop. Copy to folder uses the Windows shell's file operation (its own progress and name-conflict dialogs), so the App still never opens the media itself (AD-1).
- (decision) Open acts on one item (the focused one); it's hidden in the command bar for a multi-selection, so nobody opens 40 players.
- (decision) Selection is a set of paths. A filter or search keeps it, but actions act only on selected items that are shown; the bar counts the hidden ones. Snapshots keep it; removed items leave it; the App's own rename carries it to the new path.
- (decision) Sort: Newest first (default), Oldest first, Name, Largest, Longest, Game; unknown length last. Grouping gains None. Sort and grouping persist in LibraryViewState; search text doesn't.
- (decision) Search filters by file name as you type, case-insensitive substring; Ctrl+F focuses it, Esc clears it.
- (decision) Track Layout becomes Audio Tracks: one card per Track in file order, each listing its sound sources with a live meter; + Add sound adds a device to that Track straight from a picker with per-device meters. The separate Devices pool disappears from the UI; the Contracts devices list is derived from the Tracks' sources.
- (decision) Inputs added to a Track are marked as microphones (IsMic) by default; a source menu item 'Treat as a microphone' unmarks it. Mute is a per-Track switch shown only when the Track has a microphone. No separate advanced view.
- (decision) Presets: Simple (one Track: your PC's sound and your microphone) and For editing (Everything, Game and chat, Microphone). They need the Windows default devices: additive AudioDevice.IsDefault (AD-22).
- (decision) First run just works: when settings.json has no Global trackLayout, the engine seeds the Simple preset from the Windows default playback and recording devices, once, through its own settings queue (AD-4). Existing installs are unchanged.
- (decision) Meters next to every choice reuse meters.watch: the App adds one hidden probe Track per device it wants a level for to the watched draft. No Contracts change; if the engine's cost is too high, the story falls back to an additive per-device level list.
- (decision) Keep the draft and Save, since changes apply at the next Reset; a sticky bar at the top shows Unsaved changes with Save and Discard, and the nav item shows a dot.
- (decision) Plain page names: Track Layout -> Audio Tracks, Game Profiles -> Games, Library and Cleanup -> Storage and Cleanup. Domain words the gamer knows stay: Replay Buffer, Clip, Recording, Favourite, Hotkey.
- (assumption) Changes to Audio Tracks apply from the next Reset of the Replay Buffer (R17); the page says 'from your next game or right after your next saved Clip'. Story 10.4 checks the wording against the engine.
- (decision) Other gaps, ranked: (1) first run: nothing says which key saves a Clip and a fresh install records no sound; (2) jargon and internal ids (Track Layout, Ring folder, Draining, Reset, a profile id in the Games list); (3) the tray has only Open, Start with Windows and Quit; (4) the status header doesn't say how to save.
- (decision) A tray 'Save Clip now' item needs a new engine command and touches PRD Q-2 and the one-Save-Hotkey boundary; it's an open question for the builder at 10.1, not in scope by default.
- (event) spines finalized (headless; reviewer gate and key-screen renders deferred to story 10.1)
