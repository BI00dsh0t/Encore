# Interaction and acceptance: clip creator UX pass

## Composition

The accepted `mockup.html` governs both layout and control styling. Preserve the product's existing destinations and semantic theme colors; match the reference geometry, spacing, typography, icon weight and visual hierarchy rather than inheriting visibly different controls. The driving scene, Game/Mic names, Dashboard/Recordings placeholders and design-tweak sliders are illustrative.

The shell has a title-bar sidebar toggle, a primary navigation region and a separate bottom Settings button. The creator heading identifies the source, offers Back and places the split export action at the right. A large aspect-preserving player occupies the main area. Playback controls and Preview selection sit immediately below it, followed by a compact waveform/ruler, small pan/zoom tools, In/Out fields and selection duration. Show progress, cancellation and messages when relevant. Do not reserve permanent space for a long idle export form or repeated instructional paragraphs.

Reference sizing is a 960×900 client area at 100% scale with two tracks, in each sidebar mode. Target an approximately 400 px or taller picture and roughly 24 px waveform lanes plus a shared ruler, matching the reference proportions. These are layout targets rather than fixed heights: preserve aspect ratio, readable controls and available space at other sizes/scales. Many tracks use a bounded scrollable lane region with shared time mapping, rather than increasing the whole editor indefinitely. A track reached by keyboard must scroll into view. Smaller windows may scroll the editor; controls must not overlap, clip or disappear.

Start/end remain numeric to milliseconds, with accessible 1 ms nudges and draggable handles. Zoom buttons show plus/minus; pan buttons show left/right arrows. Tooltips distinguish timeline zoom from boundary nudges. The effective range remains visible in compact form; precision information must not be available only on hover. Do not restore the former tall waveform merely to satisfy its old minimum-height test.

## Clip range controls (R11)

Use the accepted mockup's compact range row directly below the waveform, separated by a quiet divider. At the reference width it is one row: **In**, a grouped time field and nudges; **Out**, the equivalent group; and the selected duration at the trailing edge with a small selected label. Reflow the groups at narrow widths without separating a field from its nudges. Replace the old standalone Start/End and text-heavy −1 ms/+1 ms buttons with this composition.

Each time field displays editable `HH:MM:SS.mmm` in tabular figures. Place small minus and plus icons inside its outlined group with the shared quiet surface, rounded outer corners and thin border specified by R10. A nudge changes only its associated boundary by exactly 1 ms. Tooltip and accessible names say which boundary and direction, for example Start minus one millisecond; visible In/Out labels remain associated with their fields. Timeline zoom plus/minus stays a separate group and never changes the selected range.

Waveform selection uses two compact accent handles, a thin selected-range outline and restrained translucent shading spanning the named track lanes. Handles have a visible grip, a usable pointer target and keyboard focus indication. Dragging a boundary updates the same In/Out values and selected duration; entering or nudging a valid time updates the handle position and shading. The shared ruler/playhead retains its source-time mapping. Panning a boundary outside the visible viewport must not clamp or reset it; the numeric fields still show its time.

Keep the existing keyboard boundary-selection and 1 ms trimming controls, with descriptive automation names. Commit a valid numeric edit on Enter or focus loss; arrows in an editing text field retain normal text-editing behavior rather than also panning or trimming. All input methods feed one valid requested range inside the source with In earlier than Out. Reject invalid text or a boundary that crosses the other endpoint or source limits; preserve the last valid selection and explain the problem near the range controls. Do not silently exchange endpoints, change the opposite boundary or start an export to resolve invalid input.

Selected duration is Out minus In, displayed to milliseconds with the existing nearest-millisecond correction. Keep a compact visible effective-boundary readout that identifies video-frame or audio-sample alignment when it differs from the requested range; do not overwrite the requested fields merely to show an aligned export. Editing valid boundaries invalidates stale rendered selection preview and refreshes the effective range. Preview/export cannot use an outdated range while that refresh is pending. During active render/export the range fields, nudges and drag/keyboard handles share the same editing restriction, while cancellation stays reachable.

## Control styling contract (R10)

Use the preserved mockup as the visual source. The following measurements come from its desktop styles, expressed as device-independent reference units at 100% scale. Scale with DPI and preserve usable hit targets; do not substitute the old theme's oversized, strongly bordered or differently shaped controls. Theme colors map to semantic surface/text/accent/hover tokens so Fluent light/dark and Gaming dark remain legible without losing this treatment.

| Control | Required reference treatment |
|---|---|
| Ordinary and secondary buttons | Compact, softly rounded 6-unit corners; normal 14-unit Segoe UI text; approximately 7 vertical / 10 horizontal padding. Low-emphasis icon actions are transparent at rest, with a subtle hover surface. Preview selection has the reference's quiet surface and thin border. |
| Zoom, pan and playback icons | Approximately 16×16, consistent thin-stroke weight and optical alignment. Timeline buttons use approximately 5 / 7 padding. Match the mockup symbols and silhouettes with suitable vector/native assets; a heavy or oversized glyph is not equivalent. Keep tooltips and accessible action names. |
| In/Out fields and nudges | One softly rounded, 1-unit outlined group per field, with a quiet filled input surface, tabular time text and integrated compact minus/plus nudges. Avoid separate chunky buttons or multiple nested field borders. Reference text width is approximately 115 with 7 / 8 padding. |
| Split Export action | One continuous accent-filled group, 6-unit outer corners, square adjoining edges and one subtle separator; no gap between main action and arrow. Main padding approximately 9 / 14; arrow approximately 9. Text has medium weight and a contrast-correct foreground. |
| Export dropdown | Opaque raised surface, 9-unit corners, thin quiet border, subtle shadow, approximately 5-unit outer padding and 11-unit menu-item padding. Icon, label and current-choice check align as in the reference. |
| Export popup | Approximately 440-unit reference width, 12-unit corners, quiet border, shadow and 22-unit inner padding. Inputs have 6-unit corners and 8 / 10 padding. Header, track choices, summary and secondary/primary actions preserve the reference spacing and emphasis. |
| Sidebar and Settings entry | Compact icon/label rows with approximately 10 / 12 padding, 12-unit icon-to-label gap and 40-unit row height. Selected navigation uses a soft accent surface, not a large filled card. Collapsed icons stay centered. Settings uses the same control treatment in its separate bottom region. |

Use normal/medium weights rather than bold or uppercase labels. Match the mockup's quieter secondary text and stronger primary action. Hover gives a soft surface response; keyboard focus remains a clearly visible accent outline, approximately 2 units with separation from the edge; disabled controls visibly reduce emphasis while keeping readable labels and their geometry. Define pressed states consistently with the same hierarchy. Do not let global implicit styles override icon fonts, grouped edges, padding or field geometry; use explicit scoped styles/templates where necessary.

These requirements apply to controls shown in the creator, its app-owned export surfaces and the sidebar/Settings entry. They do not redesign existing Settings page content or Windows-native destination dialogs. A matching layout with the old button/field styling fails visual acceptance.

## Export behavior

1. New creators start with Export video, preserving the existing MP4 default. The arrow opens a small menu with Export as video and Export as audio, showing the current choice. Choose one to update the main action to Export video or Export audio. Keep the source, requested selection and included tracks; refresh effective boundaries for that format and invalidate stale rendered preview.
2. The main action opens a modal options popup for that type. It must not render, open a save chooser or start export merely because the popup opened. Keep the underlying editor visible for context.
3. Show a name field, applicable format summary, named included tracks, separate/mix choice when multiple tracks are selected, and a compact selected-range/duration summary. All/None conveniences may be compact or contextual; every named track must remain selectable. With one track, avoid presenting an irrelevant mixing choice. Explain overlapping audio when mixing could double count it.
4. Video summarizes MP4 / H.264 / AAC and the existing source-resolution behavior. Multiple separate tracks mean selectable named streams in one MP4; a mix means one stream. No tracks means silent video. Audio summarizes MP3 / stereo / 48 kHz / 192 kbps; separate tracks mean named MP3 files in one directory and a mix means one MP3. Selecting no audio disables audio saving with a plain explanation. Do not show irrelevant video-only controls for MP3 or introduce unsupported codec/resolution settings.
5. Closing the popup starts no work and leaves the source/range intact. Under the recorded assumption, current track/mix choices remain available to Preview selection outside the popup; no Apply action is required. The next popup reflects those choices. Preview/export use the same effective configuration, retaining MP3 sample boundaries independently of MP4 picture alignment.
6. Save video… or Save audio… invokes the appropriate existing file chooser, or folder chooser for separate multiple MP3 files. Cancelling it starts no work. Confirming a valid destination starts one operation with current progress/cancel behavior. Repeated presses cannot launch concurrent work. Keep the source and existing output safe on collision, cancellation or failure.

The mockup demonstrates the interaction; it does not model real encoding, chooser validation, source disappearance or every disabled/busy state. Existing lifecycle rules determine those states in the product. Opening Settings is genuine navigation and follows the existing creator cancellation/disposal rules; toggling sidebar width is not navigation.

## Sidebar and Settings

- The toggle is always reachable by keyboard and pointer and exposes expanded/collapsed state. Expanded navigation shows icons and labels; collapsed navigation shows the same icons with accessible names and tooltips. Use one selected-page indication in either state. The mockup's approximately 184 px/58 px widths are reference proportions, not fixed sizing requirements.
- Toggling expands/contracts the layout and gives released space to the editor. Preserve current page, source, requested range, chosen format/audio, viewport and pending work. Reflow can request appropriately sized waveform detail; it must not reset the selection or re-open the media source.
- Settings is one dedicated bottom button in a separate layout region from the primary destinations. It remains anchored while primary navigation/content scrolls; it is not duplicated in the main list. Expanded: gear and Settings label. Collapsed: gear and Settings tooltip. Selecting it shows the existing Settings pages and active indication with existing settings/return behavior.
- Preserve actual destinations and their existing order; the mockup does not authorize inventing Dashboard or Recordings pages or moving Settings sections into top-level destinations. On narrow windows the expanded menu may overlay content rather than squeezing the editor; it must be dismissible and must not strand keyboard focus.
