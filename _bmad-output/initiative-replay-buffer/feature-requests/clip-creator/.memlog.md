updated: 2026-11-05T18:10

- (note) R1 (request, Original request): A **Create clip** action, or an equivalent clear label, is available for a Library item and the current item in the player; both open the same clip-creation workflow with that source loaded.
- (note) R2 (request, Original request): The editor offers a Twitch-style video preview and timeline with draggable start/end handles, a playhead, visible selection duration, play/pause, and playback of the selected range so the builder can check the excerpt before exporting.
- (note) R3 (request, Original request): The editor shows audio as a waveform against a time ruler, with start, end and playhead times displayed to milliseconds (`HH:MM:SS.mmm`). Start/end can be entered numerically and adjusted in 1 ms steps, alongside mouse trimming.
- (note) R4 (request, Original request): The waveform supports zooming into a chosen section and panning through it while keeping the trim selection. Zoom reveals finer source-audio detail, rather than merely enlarging an overview image; the builder can locate an audio onset and adjust a boundary at the millisecond scale.
- (note) R5 (request, Original request and Audio-mode clarification): Export audio can use one named source track or all source tracks. The builder explicitly chooses **Separate tracks** or **Combined mix**, and previews which tracks will be exported. Track names and order remain recognizable in the selection UI.
- (note) R6 (request, Original request and Audio-mode clarification): **MP4 video** and **MP3 audio-only** exports are supported. MP4 with separate tracks retains the chosen tracks as separate named audio streams in one video file; MP4 with a combined mix contains one mixed audio stream. MP3 exports either one combined audio file or separate named audio files per chosen track, as explicitly selected; tracks are never silently dropped.
- (note) R7 (request, Original request; precision implications): Export uses the selected range and audio mode, with picture and sound aligned. Audio boundaries follow decoded sample timing; video boundaries follow available source frames. The UI shows the effective export boundaries when frame alignment changes a requested millisecond value. Export must not silently widen the range to earlier/later video keyframes.
- (note) R8 (request, Original request; output implications): The builder chooses an export name and destination, sees progress, can cancel, and receives a clear success location or actionable failure. Export creates new output and preserves the source; failure or cancellation leaves no partial file presented as a completed export.
- (note) Decision: 2026-11-05, builder requested this feature and explicitly chose **both separate tracks and a combined mix**. The request is recorded; development, story slicing, scheduling and test runs have not been started.

Amend the initiative boundary and architecture when this request is scheduled.
- (note) Assumption: **Create clip** is the working action name; the exact UI and visual design still need refinement against the builder's Twitch-style reference.
- (note) Assumption: the initial scope is one contiguous range from a finished Clip, Recording or Monitor Recording. On entry from the player, start near its current playhead; the initial selection length is still to be designed. An unfinished source is unavailable for export with a clear explanation.

- (note) Assumption: the proposed default video preset is **MP4 with H.264 video and AAC audio**. This is a compatibility recommendation informed by the project's existing H.264 default and FFmpeg support, not a codec choice already approved by the builder. **WAV/FLAC** are optional audio-export candidates for further editing; additional video formats are not committed scope.
