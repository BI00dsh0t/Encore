- (direction) Fast path chosen by user; spine only (build substrate), no walkthrough
- (constraint) Initiative constraints bind: never destabilize a game (NFR-2), anti-cheat friendly with no injection/hooks/LL keyboard hooks (NFR-3), Audio Devices only, one GPU, Windows only, personal; .NET 10; separate engine process; PRD wins over PLAN.md
- (decision) AD-1 two processes [ADOPTED PLAN 1]: headless Engine owns capture, encoding, Replay Buffer, Recordings, Hotkeys, Feedback Sounds, settings file, library index, Cleanup, Game Detection; Main App (WPF) is a client for UI, Overlay, tray and engine supervision. Prevents two owners and a UI crash killing capture
- (decision) AD-2 dependency direction: App -> Contracts only; Engine host -> Core, Media, Platform adapters, Contracts; only adapter assemblies touch native interop; no assembly references between App and Engine. Prevents UI code reaching into the pipeline and interop leaking into domain code
- (decision) AD-3 IPC [ASSUMPTION]: one per-user named pipe, protocol v1, UTF-8 JSON lines with source-generated System.Text.Json; envelope {v,id,type,payload}; request/response commands plus an engine->app event stream; snapshot on connect; message types only in Contracts. Prevents two epics inventing incompatible message shapes
- (decision) AD-4 settings ownership [ASSUMPTION]: the engine is the sole writer of settings.json; App changes go through settings.update commands; atomic write (temp + replace); settings.changed broadcast. Schema: Global plus profiles keyed by normalized exe path; a profile stores only overridden keys; effective value = profile key else Global; a Track Layout is overridden as a whole, never merged per Track. Prevents epics 2/3/4 merging layouts differently and two writers
- (decision) AD-5 snapshot semantics: every capture session reads one immutable EffectiveSettings snapshot; changes apply at the next Reset or next Recording (R17); the only live mutation is mic mute state. Prevents mid-Clip setting changes producing broken files
- (decision) AD-6 clock [ADOPTED PLAN 1]: QPC ticks are the single timebase; every frame and audio buffer is stamped in QPC at capture; conversion to stream time happens only at mux. Prevents A/V drift from mixed clocks
- (decision) AD-7 media pipeline as pipes-and-filters: Sources -> Processors -> Encoders -> encoded-packet bus -> Sinks (ReplayRing, RecordingWriter). Sinks share one encoder chain only when their settings snapshots are equal; otherwise a second chain. Prevents double encoding and Recording/Clip settings bleeding into each other
- (decision) AD-8 replay ring [ADOPTED PLAN 0]: encoded packets only, in ref-counted slabs (Memory: native memory; Disk: preallocated file), keyframe index, generations on encoder restart; a save pins slabs and never blocks the writer
- (decision) AD-9 containers [ASSUMPTION]: Recordings are fragmented MP4 flushed at most every 1 s (crash safety, R11); Clips are complete MP4 with faststart written from pinned packets (best Discord/editor compatibility); AAC-LC 48 kHz per Track; Track names in title metadata; Track 1 marked default. Deviates from PLAN fMP4-everywhere for Clips
- (decision) AD-10 save cut [ASSUMPTION mechanism]: the Save Hotkey requests an IDR on the next frame so the next Clip starts on it; a Clip ends at the press frame; otherwise GOP <= 1 s
- (decision) AD-11 hotkeys [ADOPTED PLAN 7]: the engine registers every Hotkey with RegisterHotKey on a dedicated message-only window thread; the App never registers Hotkeys; no WH_KEYBOARD_LL
- (decision) AD-12 capture APIs [ADOPTED]: the game window is captured only through Windows.Graphics.Capture; Monitor Recording uses a WGC monitor item, with DXGI Desktop Duplication as a monitor-only fallback; nothing is injected
- (decision) AD-13 audio [ADOPTED PLAN 2]: WASAPI shared, event-driven; Output Devices by loopback, Input Devices by capture; bound by endpoint ID with friendly name as fallback; IMMNotificationClient rebinding; silence fill; 48 kHz float internally; a Track mix sums its sources with a limiter active only above full scale
- (decision) AD-14 interop stack [ASSUMPTION, PLAN 6 Path A]: CsWin32 for Win32/COM (D3D11, DXGI, WASAPI, MMDevice, windows, hotkeys); WGC through the Windows SDK projection selected by the TFM; FFmpeg through FFmpeg.AutoGen with FFmpeg 9.0 GPL shared builds (x264 fallback allowed: not distributed). Epic 1 bake-off may replace it with Path C (native C++ core) behind the same ports
- (decision) AD-15 Overlay and sounds [ASSUMPTION]: the Overlay is a topmost, click-through, no-activate WPF window in the Main App rendering engine events; Feedback Sounds are played by the engine; every app window sets WDA_EXCLUDEFROMCAPTURE
- (decision) AD-16 supervision [ASSUMPTION]: the Main App launches and supervises the engine (restart with backoff, status event); the engine survives the Main App exiting or crashing; a named mutex keeps one instance of each; Start with Windows launches the Main App through the HKCU Run key
- (decision) AD-17 library [ASSUMPTION]: the engine owns library.json (Favourites and file metadata keyed by path relative to the Output Folder) plus the being-written set; it watches the Output Folder and runs Cleanup; the App reads and acts through IPC commands only
- (decision) AD-18 game detection [ASSUMPTION]: the engine GameMonitor is the single owner of Game Detection and the Target Game; Game Profile id = normalized full executable path (lowercase)
